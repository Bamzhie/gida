## Project-relevant skills

Use the following available skills when they fit the task. This is a curated guide, not a requirement to invoke every skill on every change.

### Product and interface work
- `conversion-ux-review` — audit marketplace, product, signup, and checkout UX for visual friction, trust, and transparent conversion improvements; see `skills/conversion-ux-review/SKILL.md`.
- `design-taste-frontend` — design or redesign marketplace pages and components.
- `ui-ux-pro-max` — plan user flows and broader interface decisions.
- `web-design-guidelines` — review usability, accessibility, and interface consistency.
- `shadcn` — style the existing Radix-based UI components.
- `clean`, `premium` — apply a visual direction when the task calls for one.
- `image-to-code` — translate a supplied visual reference into a page or component.

### Engineering workflow
- `superpowers:brainstorming` — clarify requirements and design before feature or behavior changes.
- `superpowers:systematic-debugging` — investigate bugs and unexpected behavior.
- `superpowers:test-driven-development` — guide feature and bug-fix implementation with tests.
- `superpowers:verification-before-completion` — verify changes before reporting them complete.
- `superpowers:using-git-worktrees` — isolate work when a separate checkout is useful.
- For larger changes, use `superpowers:writing-plans` and `superpowers:executing-plans`.
- For review and wrap-up, use `superpowers:requesting-code-review`, `superpowers:receiving-code-review`, and `superpowers:finishing-a-development-branch` as applicable.
- Use `superpowers:subagent-driven-development` or `superpowers:dispatching-parallel-agents` only when parallel delegation fits the work.

### Growth and content work
- `copywriting`, `copy-editing` — create or improve marketing, landing-page, and listing copy.
- `seo-audit`, `site-architecture`, `schema` — improve search visibility, page structure, and structured data.
- `analytics`, `cro`, `ab-testing` — measure and improve conversion.

### Change tracking
- Append an entry to `CHANGE-TRACKER.md` whenever you make code changes. Summarize the change, list affected paths, and record verification that was actually run. Do not claim or include unrelated user changes.
